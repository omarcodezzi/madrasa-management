# সার্ভারে চালু করা (প্রোডাকশন)

এই গাইড ধরে নিচ্ছে একটি Linux সার্ভার (Ubuntu 22.04/24.04), কমপক্ষে ২ GB RAM (SQL Server-এর জন্য ৪ GB ভালো), আর একটি ডোমেইন নাম।
সব কিছু Docker-এ চলে: SQL Server, .NET API, Caddy (ওয়েবসাইট + HTTPS) আর রাতের ব্যাকআপ।

```
ইন্টারনেট ──443/80──▶ Caddy (web) ──▶ Angular অ্যাপ
                          └── /api, /uploads ──▶ .NET API (api) ──▶ SQL Server (db)
                                                    backup ──▶ রোজ রাতে ডেটাবেস + ছবির ব্যাকআপ
```
ডেটাবেস আর API বাইরে থেকে সরাসরি দেখা যায় না, শুধু Caddy-র ৮০ আর ৪৪৩ পোর্ট খোলা।

## ১. সার্ভার প্রস্তুত
```bash
curl -fsSL https://get.docker.com | sh          # Docker + Compose
sudo ufw allow OpenSSH && sudo ufw allow 80 && sudo ufw allow 443 && sudo ufw enable
git clone https://github.com/omarcodezzi/madrasa-management.git && cd madrasa-management/deploy
```
ডোমেইনের DNS-এ একটি **A রেকর্ড** সার্ভারের IP-তে দিন (যেমন `madrasa.example.com → 203.0.113.10`)।

## ২. গোপন সেটিং ও অ্যাডমিন পাসওয়ার্ড
```bash
./setup.sh
```
এটি ডোমেইন আর ইমেইল জিজ্ঞেস করে `deploy/.env` বানায়: SQL Server-এর পাসওয়ার্ড, JWT কী আর প্রথম অ্যাডমিনের শক্ত পাসওয়ার্ড — সব এলোমেলোভাবে তৈরি।
**অ্যাডমিন পাসওয়ার্ডটি স্ক্রিনে একবারই দেখায়, লিখে রাখুন।** `.env` ফাইলটি গোপন রাখুন এবং সার্ভারের বাইরে কোথাও নিরাপদে কপি রাখুন — এটি ছাড়া ব্যাকআপ থেকে ফেরত আনা কঠিন।

## ৩. চালু করা
```bash
docker compose up -d --build
docker compose ps            # সবগুলো "Up", db "healthy"
docker compose logs -f web   # প্রথমবার HTTPS সার্টিফিকেট নেওয়ার লগ দেখা যাবে
```
এরপর `https://আপনার-ডোমেইন` খুলে `admin` আর setup.sh-এর পাসওয়ার্ড দিয়ে ঢুকুন।
**প্রথমেই** উপরে ডান দিকের প্রোফাইল মেনু থেকে পাসওয়ার্ড বদলে নিন, তারপর সেটিংস → ইউজার থেকে বাকিদের অ্যাকাউন্ট খুলুন।

HTTPS সার্টিফিকেট Caddy নিজেই Let's Encrypt থেকে নেয় ও নবায়ন করে। পাবলিক সাইট `https://আপনার-ডোমেইন/site`।

## ৪. ব্যাকআপ
- `backup` সার্ভিস প্রতিদিন রাত ২টায় (বাংলাদেশ সময়, `.env`-এ `BACKUP_HOUR`) পুরো ডেটাবেসের ব্যাকআপ নেয়, CHECKSUM দিয়ে যাচাই করে, আর ছবিগুলোর একটি tar ফাইল রাখে। ১৪ দিনের পুরনো ফাইল মুছে যায় (`RETAIN_DAYS`)।
- এখনই একটি নিতে: `docker compose exec backup /bin/bash /backup.sh --now`
- তালিকা দেখতে: `./restore.sh`
- **সার্ভারের বাইরে কপি রাখুন।** সার্ভার নষ্ট হলে ভেতরের ব্যাকআপও যাবে। যেমন প্রতি রাতে নিজের কম্পিউটারে নামিয়ে নিন:
  ```bash
  docker compose cp backup:/backups ./backups-copy
  ```
  অথবা `rclone` দিয়ে Google Drive-এ পাঠানোর cron বসান।

### ব্যাকআপ থেকে ফেরত আনা
```bash
./restore.sh                                                    # কোন কোন ব্যাকআপ আছে
./restore.sh MMS_20261123-0200.bak.gz                     # শুধু ডেটাবেস
./restore.sh MMS_20261123-0200.bak.gz uploads_20261123-0200.tar.gz   # ডেটাবেস + ছবি
```
স্ক্রিপ্ট `RESTORE` লিখে নিশ্চিত করতে বলবে। চলমান ডেটাবেস পুরোপুরি ওই ব্যাকআপ দিয়ে বদলে যায়।

## ৫. অ্যাডমিন পাসওয়ার্ড ভুলে গেলে
```bash
docker compose run --rm -e NEW_PASSWORD='নতুন-শক্ত-পাসওয়ার্ড' api --reset-password admin
```
অন্য যেকোনো ইউজারের জন্যও একই কমান্ড (শেষে তার ইউজার নাম)। এতে অ্যাকাউন্ট আনলক হয় এবং সেই ইউজারের অন্য সব লগইন বাতিল হয়।

## ৬. আপডেট
```bash
git pull
docker compose up -d --build
```
API চালু হওয়ার সময় নতুন ডেটাবেস মাইগ্রেশন নিজেই প্রয়োগ হয়। বড় আপডেটের আগে `backup.sh --now` চালিয়ে নিন।

## নিরাপত্তা যা আছে
- HTTPS বাধ্যতামূলক (http → https), HSTS, কড়া Content-Security-Policy, ফ্রেমে খোলা নিষেধ।
- লগইন: একই অ্যাকাউন্টে ৫ বার ভুল পাসওয়ার্ডে ১৫ মিনিট লক; একই IP থেকে ৫ মিনিটে ৩০ বারের বেশি চেষ্টা আটকায়।
- পাসওয়ার্ড বদলালে, অ্যাডমিন রিসেট করলে, অ্যাকাউন্ট বন্ধ করলে বা রোল/অনুমতি বদলালে পুরনো সব লগইন ৩০ সেকেন্ডের মধ্যে বাতিল হয়।
- ছবি আপলোডে ফাইলের ভেতরের ধরন যাচাই হয় (শুধু আসল JPG/PNG)।
- প্রোডাকশনে উন্নয়নের নমুনা কী বা দুর্বল অ্যাডমিন পাসওয়ার্ড দিয়ে API চালুই হয় না; নমুনা ডেটা ঢোকে না; Swagger বন্ধ।
- SQL Server Express সংস্করণ (প্রোডাকশনে বিনামূল্যে বৈধ, প্রতি ডেটাবেস ১০ GB পর্যন্ত)।
